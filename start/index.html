Get started

Run it against your own policy.

The harness is a Python package that runs on your machine. There is no account, no upload and no hosted service — your policy and your robot model never leave your hardware.

Requires Python 3.10+ · installs MuJoCo · about two minutes

01

Install

One package, with its simulator pinned exactly. A campaign that cannot be re-run on the same physics is not evidence, so the version is not left floating.

pip install git+https://github.com/davuddevelop/faultline.git#subdirectory=harness

Check it landed: faultline version

02

Write a campaign

Scaffold a commented config. It comes pointed at a stand-in quadruped and a baseline stance controller, so it runs before you have written anything of your own.

faultline init campaign.yaml

Every field is yours. The axes are the volume to search, in physical units. The predicates are what counts as a failure — rules you wrote, checked over the whole trajectory, never a learned classifier.

# campaign.yaml
robot: my_robot.urdf
policy: mypkg.policies:WalkPolicy

seeds:                  # three, not one: a single seed hides
  sampler: 0xA13F      # which component caused a divergence
  sim: 0
  policy: 0

axes:
  push_impulse_ns: [0, 40]
  slope_deg:       [0, 25]
  sensor_lag_ms:   [0, 80]

predicates:
  - {name: tilt_limit, signal: tilt_deg, op: ">", threshold: 35.0}

search: {method: cem, budget: 150}
reduce: {enabled: true, max: 10}

03

Run it

Search the space, minimise every failure worth reporting, write the deliverables. Exit code is 1 when violations were found and 0 when they were not, so it drops into CI without a wrapper.

faultline run campaign.yaml
cem      seed=41279  failures  20/40  first at    8

2 failure mode(s) from the 10 most severe of 20:
  1.  9 x  tilt_limit via push_impulse_ns + torque_loss_pct
  2.  1 x  tilt_limit via push_impulse_ns

coverage  16/1024 cells (1.56%) at 4 bins per axis

04

Read what came out

Three things, in deliverables/.

engineering-report.md
Failures grouped by what they actually need, each with the smallest condition that still breaks the policy.
safety-appendix.md
Method, every predicate definition, what fraction of the declared space was covered, and the limits of the evidence. Written for someone assessing it rather than someone who built it.
archive/
Seeds, config hash, model hash and verdict for every run, plus a trajectory trace per failure mode. Any result can be re-executed with faultline replay.

Pointing it at your robot.

The model
URDF or MJCF. A URDF carries no contact parameters and no actuator dynamics worth trusting, so after any conversion check friction, joint damping and gear ratios before believing a result.
The policy
Anything with reset(seed) and act(obs, t). A PyTorch checkpoint wraps its forward pass in those two methods. Give it an id that identifies the checkpoint by content — paths get overwritten.
The limits
Your thresholds, on your machine. Supported signals are tilt_deg, height_m, contact_force_n and joint_vel_rads.

What this is not.

  • Not a hosted service. There is no account and nothing is uploaded.
  • Not a proof of safety. It finds failures; it cannot show their absence.
  • One robot class exercised so far, and no completed customer pilots.
  • Reproducible within one simulator build and CPU architecture, not across them.
