01

The gap

A policy that passes your test suite has only passed your test suite.

A modern robot does not run hand-written control code. It runs a neural network trained in simulation, mapping what it senses to what its motors do. It holds under the conditions it was trained on and offers no guarantee anywhere else, and nothing inside it signals when a situation is unfamiliar. It extrapolates silently, and confidently.

That breaks every instinct carried over from software testing. An ordinary program has branches you can enumerate, so 100% coverage means something. A network has none. Line coverage of the inference code reaches 100% after a single forward pass and tells you nothing at all.

The space of situations is a continuous volume. A hundred scripted scenarios tell you about a hundred points inside it.

02

Why now

20 January 2027

Regulation (EU) 2023/1230, Annex I Part A

Self-learning safety functions stop being self-certifiable.

EU Machinery Regulation 2023/1230 replaces the Machinery Directive on that date, directly and identically in every member state. Machinery with fully or partially self-evolving behaviour falls under Annex I Part A, so a notified body must be involved even where a manufacturer follows every harmonised standard.

The delegated act defining what counts as adequate evidence is not due until 2028. Assessment becomes mandatory roughly eighteen months before anyone agrees what passing looks like.

03

A run

Five stages, one question.

The question is where this policy fails. Every stage exists to answer it with something a stranger can re-run.

  1. 01

    Ingest

    Your policy checkpoint and robot model, loaded into deterministic simulation. Seed, simulator version and policy hash are recorded with every run.

  2. 02

    Perturb

    Each test is one point in the space you declared — a specific friction, slope, latency, payload and disturbance, applied together.

  3. 03

    Search

    Random sampling covers the volume. Directed search then fits a distribution to the most severe results so far and resamples, concentrating budget where violations are dense.

  4. 04

    Detect

    Each trajectory is checked against your predicates. A run is flagged only when a rule you wrote evaluates true.

  5. 05

    Reduce

    Every flagged run is minimised — perturbations relaxed back toward nominal until the failure stops firing — so what you receive is the smallest condition that still breaks the policy.

Every field is yours. The simulator version is not set here — it is recorded with each run rather than chosen.

The space

You declare the space, in real units.

No normalised knobs. An assessor reads slope 10 degrees, not slope 0.72. Seven axes are searchable today, and these are all of them.

05

The rule

A failure is a rule you wrote, not a judgement we made.

Every violation is an explicit predicate over the trajectory. No learned classifier sits between the run and the verdict, so when a run is flagged you can read the line that flagged it and disagree with it. Predicates are checked at every step of the whole trajectory, not only at the end, and they see four signals and nothing else: tilt_deg, height_m, contact_force_n, joint_vel_rads.

07

The output

Two documents, and everything needed to re-run them.

  • Engineering report

    Failures clustered by mode rather than listed by count, the region of parameter space each cluster occupies, the minimal reproducing case for every one, and trajectory traces for each flagged run.

  • Safety-case appendix

    Method, the declared space and what was covered of it, every predicate definition, and the full run manifest. Written to be read by someone assessing the evidence rather than someone who produced it.

  • Run archive

    Seeds, simulator version, policy hash and the exact configuration for every run. Any result in either document re-executes bit for bit, by you or by an assessor.

What it plugs into.

Simulator
MuJoCo, pinned at 3.12.0 — contact solvers change between minor versions, and a campaign that can’t be re-run on the same physics is not evidence
Robot models
MJCF. URDF loads, with a warning: it carries no contact parameters and no actuator dynamics
Policies
ONNX graphs and TorchScript archives, each an optional extra so neither runtime is forced on you
Predicates
YAML — a signal, an operator, a threshold and a grace period
Output
Engineering report and safety appendix in Markdown, plus an archive: run manifest, campaign and report JSON, and a trajectory CSV per failure mode
Execution
A pip-installable package. Run it inside your own infrastructure and send us the archive — it holds results, not weights

Status

What we can show, and what we can’t.

A testing company that overstates its evidence is worse than no testing company. So, plainly:

  • CanName the conditions under which a policy broke, reduce each to its smallest form, and hand over an archive where every run re-executes bit-for-bit from its seed.
  • CannotShow that failures are absent. The search finds them; no number of runs without one proves there are none left.
